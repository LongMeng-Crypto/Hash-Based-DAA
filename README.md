# DAA_FULL

`DAA_FULL` is the single-machine wrapper for the hash-based DAA prototype. It
connects issuer, TPM, host, verifier, linker, and revocation logic with one
shared protocol variable flow instead of independent proof-of-concept inputs.

## Implemented Flow

- `setup`: generates issuer SPHINCS+ keys and initializes empty revocation state.
- `join`: computes `gid`, TPM `et`, the join FAEST proof, and the issuer credential.
- `sign`: computes TPM `rho`, `msg'`, `et`, `slt`, `hk`, `pi_TPM`, and host `pi_host`.
- `verify`: checks empty revocation lists, verifies `pi_TPM`, and verifies `pi_host`.
- `link`: compares two signatures by `slt`.
- `revoke`: returns empty key and link revocation lists for the current benchmarks.

## Supported Real Parameters

The real path supports the six SHA2 SPHINCS+/FAEST-aligned parameter sets:

- `sha2-128s` maps to `sphincs-sha2-128s` and `FAEST-128s`.
- `sha2-128f` maps to `sphincs-sha2-128f` and `FAEST-128f`.
- `sha2-192s` maps to `sphincs-sha2-192s` and `FAEST-192s`.
- `sha2-192f` maps to `sphincs-sha2-192f` and `FAEST-192f`.
- `sha2-256s` maps to `sphincs-sha2-256s` and `FAEST-256s`.
- `sha2-256f` maps to `sphincs-sha2-256f` and `FAEST-256f`.

The host proof is generated by:

```text
DAA_HOST/risc0_sha256_backend_fork/daa_host_proof
```

The wrapper uses the SHA-256 RISC0 backend and records the internal
`prover_ms` / `verifier_ms` metrics emitted by that runner. The top-level
`wall time` includes Cargo/RISC0 wrapper overhead, so use the benchmark step
table for protocol analysis.

## Proof Modes

- `simulated`: deterministic simulated proofs for fast protocol plumbing tests.
- `real-tpm`: real FAEST join and TPM signing proofs, simulated host proof.
- `real-128s`: real FAEST proofs and real RISC0 SHA-256 host proof. The name is
  kept for CLI compatibility, but it now works for all six SHA2 parameter sets.

## Shared Build Cache

If `CARGO_TARGET_DIR` is not already set, `DAA_FULL` now uses:

```text
/tmp/sedaa-risc0-shared-target
```

This lets the default and `segment-po2=20` runs share CUDA/RISC0/Cargo build
artifacts. Different SPHINCS+ parameter sets still need their own first guest
build, but the shared target directory reuses as much common build output as
Cargo/RISC0 allows.

You can also set it explicitly before a long benchmark session:

```sh
export CARGO_TARGET_DIR=/tmp/sedaa-risc0-shared-target
```

## Commands

Run the full protocol once with defaults:

```sh
cargo run -p daa_cli -- run-full
```

Run a fast plumbing-only benchmark:

```sh
cargo run -p daa_cli -- bench \
  --proof-mode simulated \
  --iterations 3 \
  --json results/bench_simulated.json
```

Run a real TPM-proof smoke test without the expensive RISC0 host proof:

```sh
cargo run -p daa_cli -- bench \
  --params sha2-128s \
  --proof-mode real-tpm \
  --iterations 1 \
  --json results/bench_real_tpm_128s.json
```
